# GeDefense Linux 6.1.1 — Hotfix Release Note

Date: 2026-11-19. Previous tag: `v6.1.0` (`6.1.0`). Target release: **6.1.1** (`VERSION = 6.1.1`).

## Why this hotfix exists

6.1.0 shipped the Module A–E feature set but was blocked by the confirmed
findings of the 2026-11-18 and 2026-11-19 security audits, and rejected the
32-byte BTF v1 header that Kernel 7.3 uses. 6.1.1 is the deployable release for
the 6.1 line.

## Kernel compatibility

`rust/gedefense-core/src/btf_offsets.rs` accepts `24 <= hdr_len <= data.len()`
instead of requiring exactly 24 bytes, so the 32-byte BTF v1 header of
Kernel 7.3 parses. Section offsets are computed with `checked_add`; headers
shorter than 24 bytes, longer than the image, or truncated remain fail-closed.
Regression tests: `titan_btf_accepts_extended_v1_header`,
`hdr_len beyond image` in `titan_btf_rejects_broken_headers_truncation_and_implausible_layouts`.

### Cockpit & Operator UX

- **Two-stage traffic-light auto-cooldown (`control/overview_situation.go`):**
  Worker crash storms and unmitigated critical/high alerts keep the hero
  traffic light on RED for the active `15m` escalation window, step down to
  YELLOW during the `15m–60m` post-incident observation window if no new
  crashes/alerts occur, and automatically return to GREEN (`calm_mitigated`)
  once subsided (`> 60m`) while retaining 24h metrics. Covered by
  `TestBuildOverviewSituationTrafficLights`.

## Upgrade notes

- Replace the binaries/units and restart `gedefense-capture-helper.service`
  before `gedefense-control.service` (the helper owns the raw capture socket).
- The settings schema stays **v18**; no migration beyond 6.1.0 is required.
- Re-run `gedefense-control --preflight` and verify
  `/api/v1/tls-sensor/status`, `/api/v1/worker-guard/status`,
  `/api/v1/web-exposure/status` and `/api/v1/lpe-guard/status` after the
  upgrade.
