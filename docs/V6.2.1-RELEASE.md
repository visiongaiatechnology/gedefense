## 1. What changed from 6.2.0 to 6.2.1

### Kernel BPF-LSM Malware Inode Quarantine Lock & Core Boundary (`FIND-G-001`)
- **Core quarantine path boundary (`rust/gedefense-core/src/quarantine.rs`):** Enforced an explicit path allowlist (`CORE_QUARANTINE_ALLOWED_ROOTS`) and forbidden-root denylist (`CORE_QUARANTINE_FORBIDDEN_ROOTS`, covering `/proc`, `/sys`, `/run`, `/boot`, `/bin`, `/sbin`, `/lib*`, `/usr`, `/etc`, `/var/lib/vgt`, `/etc/vgt`, `/opt/vgt`, and `/dev` except `/dev/shm`) directly inside `decode_path()`, plus `capture_open_fd_only()` for post-inode-lock encrypted Vault archival without granting `CAP_DAC_OVERRIDE` or `CAP_DAC_READ_SEARCH`.
- **Kernel inode lock (`rust/gedefense-ebpf/src/credential_guard.rs`, `rust/gedefense-core/src/on_write.rs`):** Added `MALWARE_DENIED_INODES` (`HashMap<[u8; 16], u8>`, capacity `4,096`) to deny `file_open` with `-EACCES` before the `guard_active()` short-circuit for any non-`gedefense-` process when `OnWriteSensor` encounters a non-root `0755` directory where unlinking is refused with `EACCES`, while encrypting the sample into the Quarantine Vault (`"on-write-inode-locked"`). Raises `hardred-malware` score from `65.6` (`33.3%` prevention TPR) in `6.2.0` to **`95.6` (`100.0%` prevention TPR)** in `6.2.1`.

### Kernel Behavioral XDR Probes, Subshell `argv` Capture & Multi-CPU Tracepoint Fix
- **Kernel probes (`rust/gedefense-common/src/xdr_kernel.rs`, `rust/gedefense-ebpf/src/xdr_kernel.rs`, `rust/gedefense-core/src/xdr_kernel.rs`, `control/xdr_kernel.go`, `control/coreipc_xdr_kernel.go`, `control/xdr_rules.go`):**
  - `EXEC_ARGV_EVENTS` (`512`-byte ring record) + `PENDING_EXEC_ARGV` captures `sys_enter_execve`/`execveat` `filename` and `argv[1..4]` per TID and flushes on `sched_process_exec` (`gedefense_exec`) with updated `comm`.
  - `KERNEL_PROBE_EVENTS` (`64`-byte record) captures `sys_enter_ptrace` (`XDR.PTRACE_ATTEMPT`), `socket_create` BPF-LSM global denials for `IPPROTO_SCTP`/`DCCP`/`RDS` (`XDR.KERNEL_PROTOCOL_PROBE`), `sys_enter_openat`/`openat2` credential probes (`XDR.CREDENTIAL_PROBE`), and `sys_enter_symlinkat`/`symlink` over `/etc` and sensitive targets (`XDR.SYMLINK_OVER_SENSITIVE`), plus discovery rules `KD.LINUX.DISCOVERY.ACCOUNT` and `KD.LINUX.DISCOVERY.SUID`.
  - `PENDING_COLD_OPEN` + `#[kretprobe] gedefense_getname_flags_ret` on `getname_flags` reads kernel `struct filename->name` via `bpf_probe_read_kernel_str_bytes` when userspace `.rodata` string pages have not yet been demand-paged at `sys_enter_*`.
- **Multi-CPU tracepoint activation (`rust/vendor/aya/src/programs/trace_point.rs`, `mod.rs`, `sys/perf_event.rs`):** Enables per-CPU perf tracepoint file descriptors across `online_cpus()` while attaching the single shared eBPF program entry cleanly across multi-vCPU kernels.

### Production Service-Pool Isolation & Control-Plane Telemetry Hygiene
- **Ransomware & pool-worker isolation (`rust/gedefense-common/src/ransom.rs`, `rust/gedefense-core/src/{ransom.rs, process_tree.rs}`, `rust/gedefense-ebpf/src/ransom.rs`):** Tightened `RANSOM_ENTROPY_DISTINCT_THRESHOLD` (`15 -> 6`) and `RANSOM_META_THRESHOLD` (`25 -> 18`), added `RANSOM_TRUST_POOL_METADATA` (`2u8`) so pooled web/DB daemons (`php-fpm*`, `lsphp*`, `httpd`, `apache2`, `nginx`, `openlitespeed`, `lshttpd`, `mariadbd`, `mysqld`, `postgres`, `redis-server`, `memcached`, `gitea`) do not false-trigger on routine cache/temp renames while preserving high-entropy `ENTROPY_BURST` detection, and isolated compromised pool workers via PPID-only `stop_process_descendants` / `collect_tree` (keeping master daemons and healthy worker siblings online).
- **StyX beacon filter & async Chronos FIM (`control/styx_beacon.go`, `control/xdr.go`):** Added `isIgnoredNonExternalFlow` to suppress loopback (`127.0.0.0/8`, `::1`), link-local/multicast, and unattributable kernel softirq/timer traffic (`pid=0` / `swapper/*` / `DstPort=0`); moved `ChronosScanner.Scan` into an atomic-guarded background goroutine (`chronosRunning`); and tightened healthy `StyxFlowHealth` polling to `1s`.
