# GeDefense 6.1.2 Hotfix Release Note (2026-11-20)

`6.1.2` is a targeted installer and reliability hotfix on top of `6.1.1` (`bdba88e`). All kernel, eBPF, cryptographic, and HTTP security logic from `6.1.1` remains unchanged; `6.1.2` fixes four missing systemd unit preconditions on fresh OneClick installs and eliminates a 1-in-256 Ed25519 key-file parsing flake.

## Fixed in 6.1.2

### 1. Fresh-Install Systemd Unit Preconditions (`scripts/oneclick-installer-header.sh`)
Checking all six runtime `.service` units shipped in `6.1.1` (`gedefense-bpffs.service`, `gedefense-core.service`, `gedefense-capture-helper.service`, `gedefense-control.service`, `gedefense-access.service`, `gedefense-cell-helper.service`) revealed four preconditions that previously depended on a reboot running `systemd-tmpfiles`:

1. **`gedefense-desktop` system group missing in `ensure_service_accounts()`:**
   `gedefense-control.service` sets `SupplementaryGroups=gedefense-l7 gedefense-desktop` and `packaging/tmpfiles/vgt-gedefense.conf` sets `d /run/gedefense 2750 gedefense gedefense-desktop -`, but `ensure_service_accounts()` only provisioned `gedefense`, `gedefense-l7`, and `gedefense-access`. Both `systemd-sysusers` and the `groupadd --system` fallback now create and verify `gedefense-desktop`.
2. **`/run/gedefense-scan` (`0750 root:gedefense`) missing before reboot:**
   `gedefense-core.service` lists `/run/gedefense-scan` in `ReadWritePaths=` without the optional `-` prefix, while `install_units()` only installed `vgt-gedefense.conf` without running `systemd-tmpfiles --create` for it. `ensure_user_and_dirs()` now creates and verifies `/run/gedefense-scan` (`0750 root:gedefense`).
3. **`/run/gedefense` (`2750 gedefense:gedefense-desktop`) missing before reboot:**
   `gedefense-control.service` lists `/run/gedefense` in `ReadWritePaths=` without `-`. `ensure_user_and_dirs()` now creates and verifies `/run/gedefense` (`2750 gedefense:gedefense-desktop`).
4. **`/sys/fs/cgroup/vgt-cells` (`0775 gedefense:gedefense`) created too late:**
   `gedefense-cell-helper.service` starts `Before=gedefense-control.service` and specifies `ReadWritePaths=/sys/fs/cgroup/vgt-cells` without `-`, whereas previously only `gedefense-control.service` created it in `ExecStartPre`. `ensure_user_and_dirs()` now creates and verifies `/sys/fs/cgroup/vgt-cells` (`0775 gedefense:gedefense` when `/sys/fs/cgroup` exists) before any unit is started.

All four invariants are now enforced by `server_installer_hardening_gate()` in `scripts/tests/check_installer_templates.sh`.

### 2. Canonical TLS Certificate Path & Early `--help` (`scripts/oneclick-installer-header.sh`)
- `CERT_FILE` is now pinned to `"${TLS_DIR}/access.crt"` (`/etc/vgt/gedefense/tls/access.crt`, mode `0644 root:gedefense`) instead of `"${ACCESS_DIR}/access.crt"`, matching `gedefense-access.service.in` (`ExecStartPre=+/usr/bin/install ... /etc/vgt/gedefense/tls/access.crt /etc/vgt/gedefense-access/access.crt`), `gedefense-provision`, `gedefense-app`, and `gedefense-ensure-ready`. On fresh installs, `generate_tls()` writes `/etc/vgt/gedefense/tls/access.crt` and installs the served copy `/etc/vgt/gedefense-access/access.crt` (`0644 gedefense-access:gedefense-access`); on upgrades from older OneClick releases where only `${ACCESS_DIR}/access.crt` existed, it migrates the certificate into `${TLS_DIR}/access.crt` first.
- `-h` / `--help` is evaluated before the root check (`EUID == 0`) and `/var/log/vgt-gedefense-install.log` initialization so `./VGT_GeDefense_V6_6.1.2_OneClick.run --help` works without `sudo` (matching `ONECLICK-INSTALL.md`), while actual installation still strictly requires root.
- `scripts/build-desktop-oneclick.sh` writes relative filenames into `GeDefense-6.1.2-Desktop-OneClick.run.sha256` so `sha256sum --check` works on target hosts.

### 3. Upgrade Status JSON Guard (`scripts/oneclick-installer-header.sh`)
`reconcile_post_upgrade_posture()` now catches empty or non-JSON responses in both Python parsers (matching `capture_pre_upgrade_status()`), preventing a spurious `JSONDecodeError` message if `/api/v1/status` returns an empty body during restart.

### 3. Feed Signing Key `0x0d` Trailing-Byte Flake (`control/feed_signing.go`)
When a randomly generated 32-byte Ed25519 seed (or 64-byte private key) happens to end with byte `0x0d` (`\r`) and a single `\n` terminator is appended (`len == 33` or `65`), `feedSigningKeyFileBytes()` previously checked `raw[len-2] == '\r' && raw[len-1] == '\n'` before checking `len - 1` against `rawSizes`, truncating the valid key to 31 (or 63) bytes. The helper now checks single-LF length validity before stripping `\r\n`, and `TestFeedSigningKeyFileBytesAreNotTrimmed` includes deterministic `0x0d` seed/key regression cases.
