# GeDefense Linux V6.3.0 — Release Notes

**Release date:** 2026-11-24
**Base:** GeDefense Linux 6.2.1 (`VERSION = 6.2.1`) → **6.3.0**
**License:** AGPL-3.0-only · **Platform:** Linux x86_64 (eBPF/XDP data plane, Go control plane, Rust core)

V6.3.0 is the anti-spyware / eBPF-rootkit-defense release. It hardens the sensor
against `LD_PRELOAD`/libc tampering, closes the syscall-bypass and `comm`-spoofing
gaps of the previous sensor generation, adds the 8-domain cross-view verifier,
StyX phase 2 (ingress/PCR, DNS tunnelling), the GIEF v1.0/SBC evidence model, the
unified PermitV1 broker with a persistent review queue, and the opt-in Chameleon
identity profile — plus the remaining ARES self-defense items (TUF-grade feed
anti-poisoning `S09`, telemetry anti-DoS backpressure `S12`, management-API RBAC
`R6`, anti-truncate witness priority push `S08`/`S15`).

> **Benchmark honesty.** The published VGT HardRed **`94.73 / 100 (PASS)`** and
> REDHARD ARES 1.2 results in the READMEs were measured on **6.2.1**. There is
> **no new HardRed/ARES benchmark run for 6.3.0**, and this release claims no new
> score. 6.3.0 adds the AP-0…AP-9 sensor/self-protection features and their
> verification evidence on top of that measured baseline.

## 1. Feature map (AP-0 … AP-10)

### AP-0 — Static musl core & sensor self-protection
- `gedefense-core` builds as a **static musl binary** (`static-pie`, `readelf -d`
  reports no `NEEDED`), removing glibc/`LD_PRELOAD` attack surface for the
  privileged sensor.
- BPF pin guard, ring-buffer drop accounting and periodic canary self-test report
  `XDR.SELF_TAMPER` / `SBC-EVID-08` health facts; release eBPF object is built
  from the pinned nightly and installed only after verification.

### AP-1 — Executable-inode trust instead of spoofable `comm`
- `credential_guard`/`ransom` trust decisions now use BTF-resolved
  `task_struct -> mm -> exe_file -> f_inode` identity against
  `TRUSTED_EXEC_INODES` (dev, ino) bitmasks, populated by the core via
  `openat2(RESOLVE_NO_SYMLINKS)`; `prctl(PR_SET_NAME)` spoofing no longer
  impersonates an allowlisted reader.
- `MALWARE_DENIED_INODES` accepts behavioural-carrier inode locks (LD_PRELOAD
  `.so`, BPF loaders, memfd carriers) with TTL/restore and hash in the ledger.

### AP-2 — Attach-time eBPF guard and helper-risk bitmap
- `lsm/bpf_prog` + `tp/syscalls/sys_enter_bpf` + BTF-gated
  `kprobe/check_helper_call` capture raw helper IDs before `do_misc_fixups` and
  build a per-program risk bitmap (`bpf_probe_write_user`,
  `bpf_override_return`, `bpf_send_signal`).
- New observe-first rules `XDR.BPF_ANOMALY`, `XDR.BPF_ROOTKIT_HELPER`; own
  PID/inode excluded, security-tool loaders routed through PermitV1 TOLERATED.

### AP-3 — 8-domain cross-view verifier
- Kernel iterators (`task`, `tcp`, `udp`, `bpf_prog`, `bpf_map`) and
  `lsm/socket_create`/`socket_setsockopt`/`kprobe/sk_attach_filter` feed an
  independent cross-view engine: eBPF ID-gap scan (`GET_NEXT_ID` vs direct
  `GET_FD_BY_ID`), `NETLINK_SOCK_DIAG` (`inet_diag_req_v2`,
  `packet_diag_req` + `PACKET_SHOW_FILTER`) without invoking `ss`,
  `iter/task` vs `getdents64` vs direct `/proc/<pid>/stat`, LKM/ftrace cross-view,
  library/map-pin cross-view. Reports `XDR.HIDDEN_BPF_PROG`,
  `XDR.HIDDEN_PROCESS`, `XDR.HIDDEN_SOCKET`, `XDR.PORTLESS_RAW_TAP`,
  `XDR.LKM_HIDDEN`, `XDR.FTRACE_HOOK_ANOMALY`, `XDR.BPF_LINK_TAMPER`
  (observe-only; fixed tap allowlist for tcpdump/dhclient/NetworkManager/lldpd/
  keepalived/suricata).

### AP-4 — io_uring bypass closure & LKM hooks
- BTF-optional LSM hooks `uring_override_creds`/`uring_sqpoll`/`uring_cmd`,
  io_uring tracepoints and pre-stealth `module_load`/`init_module`/
  `finit_module`/`delete_module` capture feed `XDR.IO_URING_ANOMALY` and
  `XDR.LKM_LOAD`.
- Opt-in sysctls only: `kernel.io_uring_disabled` (never default 2) and
  `vm.memfd_noexec=2`; custom hardening mask extended to `0x00df_ffff`
  (bits 0‑20, 22, 23; bit 21 stays reserved).

### AP-5 — Persistence, linker, PAM/sshd and peripheral integrity
- Write/audit protection for `/etc/ld.so.preload`, linker config and
  `ld-linux-*.so`, package-DB verification for libraries mapped into
  `sshd`/`sshd-session`/`sudo`/`su`/`login`/`curl` (Ebury/Plague/xz-style
  implants), systemd generator/drop-in, udev `RUN+=`, PAM and
  `authorized_keys`/`sshrc` integrity.
- Desktop peripheral sensors (`/dev/video*`, `/dev/snd/*`, PipeWire/Pulse,
  `/dev/input/event*`), user/browser secrets (`~/.ssh`, `~/.gnupg`, `~/.aws`,
  browser credential DBs, keyrings) and `process_vm_readv/writev`,
  `/proc/*/mem`, `ptrace_access_check` → `XDR.PERIPHERAL_BG_ACCESS`,
  `XDR.EVDEV_KEYLOG_PROBE` and related observe-only findings.

### AP-6 — StyX phase 2, DNS tunnelling, GIEF v1.0 / SBC
- New `cgroup_skb/ingress` observer makes `RxObservationAvailable` real;
  bidirectional PCR = `(tx-rx)/(tx+rx)` over 5-minute windows per
  entity/target, `XDR.STYX_PCR_EXFIL` only when PCR > 0.60 exactly with
  ≥ 256 KiB and a real ingress observation (honest `NONE`/`TEMPORAL` otherwise).
- Bounded UDP/53 capture (`sendto`/`sendmsg`) feeds a 5-signal DNS tunnelling
  analysis (Shannon entropy > 3.5, Zipf divergence ≥ 3.0, FQDN > 50,
  TXT/NULL > 10 %, > 100 subdomains/h); `XDR.DNS_TUNNEL` requires **≥ 3
  simultaneous signals**, benign CDN domains do not fire.
- `gief/v1.0` envelope on every finding (capability block, correlation quality,
  `SBC-PROV-01`…`SBC-EVID-08` families, evidence hashes, blindspots) and a
  time-weighted SBC entity graph (30-minute half-life, bounded, metadata only,
  byte-identical decision fields verified in tests).

### AP-7 — PermitV1 broker, review queue, prune, explainability
- Unified `vgt-gedefense-permit-v1` object (`AUTHORIZED`/`TOLERATED`/
  `ANALYST_MODE`, SHA-256/Inode, allowed parents, scope, TTL, Ed25519 ledger
  audit, encrypted store). Unsigned or corrupt permits can never become
  `AUTHORIZED`; suppression-only — the broker never escalates or kills.
- Built-in TOLERATED profiles for dev toolchains, container runtimes, security/
  observability tools and web-service pools, keeping the `0.0 %` protection-FP
  gate intact.
- Persistent, encrypted, TTL-bounded review queue with capacity + 256 MiB disk
  reserve, `QUARANTINE_PRUNE` (evidence-first Rust core + API), and mandatory
  explainability fields on every XDR finding
  (`stages`, `rules`, `evidence_hashes`, `capability_status`,
  `exonerating_evidence_hint`, `blindspots`).

### AP-8 — Chameleon Identity Mode (opt-in install profile)
- Default-off installation profile: bounded signed manifest gives neutral
  sockets/paths/ports and **same-length neutral rename** of every kernel-visible
  eBPF program/map identifier at load time (ELF `.strtab` patch + `Ebpf::load`,
  section names intact), so `bpftool prog list` shows no
  `gedefense`/`styx`/`titan` strings. Any invalid/missing manifest is fatal —
  an opted-in host never silently reverts to the public identity.
- The privilege boundary remains inode + HMAC + `SO_PEERCRED`; the admin keeps
  the real mapping through the signed evidence commitment and a 0600 audit
  file. Full neutral unit/binary renaming is documented as not implemented.

### AP-9 — ARES self-defense
- **`S09` TUF-grade feed/rule anti-poisoning:** `2-of-3` Ed25519 threshold
  signatures, root/content/snapshot role separation, short `expires_at`,
  strictly monotonic anti-rollback epoch, local semantic guard before activation
  (≤ 20 % deletion diff budget, untouchable system-path zone, no global
  wildcard allowlists, RE2 complexity check), parser-cell isolation and
  Last-Known-Good rollback.
- **`S12` telemetry anti-DoS:** independent `SEC_CRIT_EVENTS` high-priority ring
  (256 KiB) plus per-`(class, cgroup, uid)` token buckets (512 tokens /
  512 per second) for every bulk emitter; critical evidence can never be
  displaced by exec/log spam, aggregate suppression is reported as
  `XDR.TELEMETRY_FLOOD_SUPPRESSION`, and controlled overflow sets
  `capability.degraded` instead of failing open. Quotas are reported honestly
  (`enforced=false` where the owning module does not yet enforce).
- **`R6` management-API RBAC:** Observer (read-only) / Operator / Critical-Unlock
  roles enforced server-side; step-up via dedicated HMAC proof or gateway
  password re-authentication (short-TTL, single-use, replay-cached, HMAC-signed
  gateway claim); bounded brute-force lockout; existing operator behaviour
  preserved.
- **`S08`/`S15` anti-truncate:** `SBC-EVID-08`/self-tamper evidence is handed to
  the out-of-band witness **before** the local forensic log append (bounded,
  deduped, non-blocking); without witness the capability is explicitly reported
  as not ROBUST.

### AP-10 — Tests, verification, release engineering
- New rejecting-decoder tests for every wire struct, BTF-inode/prctl-spoofing
  negative tests, BPF ID-gap and sock_diag loopback tests, S09 poison corpus,
  S12 flood/critical-ring smoke, PermitV1 never-auto-block tests and the full
  Go/Rust/audit gate matrix (see §3).
- Quality pass: V6.3.0 production files split to the VGT ≤ 500-line guideline;
  the remaining pre-existing large files are scheduled for the post-release
  structural refactoring waves (structure-only, gated per wave).
- Atomic version bump `6.2.1 → 6.3.0` across `VERSION`, Control, Gateway, Rust
  workspace + `Cargo.lock`, AstraeaOS contract, Arch `PKGBUILD`, OneClick
  headers, READMEs, `CHANGELOG.md` and `RELEASE-NOTES.md`.

## 3. Security invariants preserved

- **Kill gate unchanged:** a response score ≥ 120 **and** ≥ 2 independent
  kill-eligible categories, evidence commit after; all new detectors are
  Observe-only (`Decision: "alert"`, `Action: "none"`), never kill-eligible on a
  single signal. PermitV1 is suppression-only; the dev-build simulation produced
  **0 auto-kills**.
- **Systemd sandbox unchanged:** no `CAP_DAC_OVERRIDE`, `ProtectSystem=strict`,
  `PrivateTmp=false`; only targeted `ReadOnlyPaths`/`ReadWritePaths` grants for
  the new kernel views.
- **Wire contracts:** every new `#[repr(C)]` record has a strict rejecting
  decoder (fixed size, zero reserved bytes, NUL-padded `comm`, unknown
  source/kind/action rejected); new VGT3 commands are additive and
  version-tolerant.
- **Zero new dependencies:** Go stdlib only; Rust pinned/vendored crates only;
  `--locked` builds.
- Feed/rule activation remains signature-gated plus the local semantic guard;
  no new cloud/server dependency, no outbound control plane.

## 4. Upgrade & compatibility notes

- `gedefense.toml` remains backward compatible; PermitV1 profiles are additive
  TOLERATED overlays and can be disabled to return to the previous allowlist
  behaviour.
- Hardening custom mask is now `0x00df_ffff`; existing persisted 21-bit profiles
  remain valid, bit 21 stays reserved.
- `kernel.io_uring_disabled` and `vm.memfd_noexec` remain **opt-in**; defaults do
  not change.
- Chameleon is off unless an installation manifest is supplied via
  `--chameleon-manifest` / `VGT_INSTALL_MANIFEST`; the core and control plane
  fail hard on an invalid manifest rather than fall back silently.
- The review queue is persistent; its 256 MiB disk reserve and TTL (7 days)
  default are documented in `docs/V6.3.0-PLAN.md`.
- RBAC defaults preserve the existing operator token behaviour; Observer and
  Critical-Unlock are optional provisioning files
  (`docs/V6.3.0-RBAC.md`).
