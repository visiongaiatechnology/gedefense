### AP-8 Chameleon Identity Mode (opt-in install profile)
- Strict bounded manifest (`vgt-gedefense-chameleon-v1`, ≤16 KiB, owner/mode
  policy, absolute canonical paths, 32-byte salt, loopback-only ports); any
  invalid/missing manifest is **fatal** — an opted-in host never silently falls
  back to the public identity; no manifest = byte-identical default behaviour.
- Kernel-visible program/map names are renamed once at load: same-length
  HMAC-SHA256-derived neutral names appended to the string table and the managed
  symbols repointed (section names untouched, BTF-bearing objects refused,
  forbidden markers re-derived). Real-object test: **174 symbols renamed,
  3,741 neutral bytes appended**, `aya` then parsed **44 programs / 132 maps**;
  no managed public identifier survives in the kernel-visible string table.
- `ManagedEbpf` resolver threads the mapping through every core loader;
  `chameleon::map_name`/`program_name` are identity when disabled (tested).
- Control profile applies only installation-specific paths/ports (core socket,
  scan socket, loopback backend port, policy/incident/behavior/settings/release/
  feed paths); keys, TLS, token, feature toggles untouched. The signed evidence
  ledger records one `chameleon.profile.active` commitment (install id +
  salt fingerprint + mapping hash, no secret); core writes a 0600
  `chameleon-map.audit` mapping for the admin.
