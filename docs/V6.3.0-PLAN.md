## 1. Non-negotiable engineering rules (from the guide + VGT standards)

1. **Zero new dependencies.** No new Cargo crates, no CGO in `control/`, Go
   stdlib only, direct `libc::syscall` for Linux-only operations.
2. **eBPF verifier discipline.** `rust/gedefense-ebpf/**` and `#[inline(always)]`
   helpers in `gedefense-common`: no `&[&str]` static slice tables, no dynamic
   allocation, no unbounded loops, no hard-coded kernel struct offsets. Offsets
   come from BTF via `btf_offsets.rs`/`btf_validate.rs` and are published through
   an eBPF array map; a BTF failure means **fail-open + explicit degradation**,
   never a lockout.
3. **Rejecting wire decoders.** Every new `#[repr(C)]` ring record has an exact
   fixed byte size, zero reserved bytes, NUL-padded `comm`/strings and a decoder
   that returns `Option::None`/`Err` for anything the producer cannot emit.
   Never repair silently.
4. **`VGT3` IPC is append-only/versioned.** New commands are new names; old
   command shapes stay byte-identical. Every new parser gets a `FuzzCore*`
   target in `control/`.
5. **Kill gate unchanged.** `Score >= 120` **and** `>= 2` independent
   kill-eligible categories (`combineMatches` in `control/xdr_rules.go`). Every
   new detector starts in **Observe**: `KillEligible=false`, no response action
   from a single event. Dev/build/container/security tools are TOLERATED
   (`cargo`, `go`, `gcc`, `npm`, `docker`, `containerd`, `runc`, `bpftrace`,
   `perf`, `tcpdump`, `gdb`, `syncthing`, `php-fpm`, `nginx`, `mariadbd`).
6. **systemd sandbox stays strict.** No `CAP_DAC_OVERRIDE`, no
   `ProtectSystem` weakening, no `PrivateTmp=true`. New reads are explicit
   `ReadOnlyPaths`, new writes are exact single-node grants.
   `./scripts/security-audit.sh` must stay green after every AP.
7. **Proof before status.** Each AP reports `DONE_VERIFIED`,
   `IMPLEMENTED_NOT_VERIFIED`, `BLOCKED` or `DEFERRED` with the exact command,
   exit code and environment. Linux-kernel runtime behaviour that cannot be
   exercised on this host is `NOT_TESTED`, never "PASS".

## 4. Work packages

### AP-0 — static musl binary, pin manifest, ring-drop self-tamper, canary self-test
- **Build:** `Makefile` target `rust-core-musl` (musl static, `ldd` says
  "not a dynamic executable"), `docs`/CI wiring.
- **Core (`rust/gedefense-core/src/self_defense.rs`):** pin critical maps under
  `--bpf-pin-root` (default `/sys/fs/bpf/gedefense`), keep an expected pin
  manifest, re-verify on poll; synthetic canary self-test through the existing
  `CanaryBroker`; bounded tamper queue.
- **Control (`control/coreipc_selfguard.go`, `control/xdr_selfguard.go`):**
  `SELF_GUARD_STATUS`/`SELF_TAMPER_EVENTS`/`SELF_GUARD_SET` parsers; ring-drop
  watchdog over `CRED_GUARD`, `STYX_FLOW`, ingress and `EXEC_ARGV` counters →
  evidence-first `XDR.SELF_TAMPER` incidents tagged `SBC-EVID-08`, observe-only.
- **Acceptance:** musl artifact static on a Linux build host; an unlinked pin, a
  dead canary chain or a new high-priority ring drop produces a self-tamper
  record within one poll interval (≤5 s). Static gates green.
- **Verification class on this host:** `IMPLEMENTED_NOT_VERIFIED` for the live
  rm/BPF path; parser/unit tests runnable.

### AP-1 — executable-inode identity instead of spoofable `comm`
- **Common (`rust/gedefense-common/src/exec_inode.rs`):** 16-byte identity key
  `(s_dev LE u32, i_ino LE u64, 4 zero)`, flag bitmask
  `ALLOW_CRED_READ=1`, `ALLOW_RANSOM_FULL=2`, `ALLOW_RANSOM_POOL_META=4`,
  `ExecInodeEvent` 64-byte rejecting decoder, state-word ABI.
- **Core (`rust/gedefense-core/src/exec_inode.rs`):** mandatory
  `EXEC_INODE_*`/`TRUSTED_EXEC_INODES` maps, BTF resolution of
  `task_struct→mm→exe_file→f_inode`, `openat2(RESOLVE_NO_SYMLINKS)` path
  resolution, default trusted contract (`sshd`, `sshd-session`, `sudo`, `su`,
  `passwd`, `chpasswd`, `login`, `unix_chkpwd`, `systemd*`, `gedefense-*`, …),
  TTL malware inode locks, `EXEC_INODE_*`/`MALWARE_INODE_*` commands.
- **eBPF (`rust/gedefense-ebpf/src/exec_inode.rs` + edits to
  `credential_guard.rs`, `ransom.rs`):** inode gate as primary check with
  comm-fallback only when BTF/offsets are unavailable (audited as degraded);
  credential deny event action distinguishes inode denial; ransom trusted tiers
  keyed on the exe inode.
- **Control (`control/coreipc_execinode.go`, `control/xdr_execinode.go`):**
  strict parsers, `XDR.NAME_PATH_MISMATCH` evidence for comm/executable
  divergence, capability/status projection, observe-only.
- **Acceptance:** `/tmp/fake_sshd` that calls `prctl(PR_SET_NAME,"sshd")` and
  opens `/etc/shadow` receives `-EACCES` and produces
  `XDR.CREDENTIAL_READ_BLOCKED`; corpus test proves the inode gate rejects the
  spoof. Unit/rejecting-decoder tests green; Rust+Go typechecks green.

### AP-2 — attach-time eBPF guard and helper-risk bitmap
- **Common (`bpf_guard.rs`):** 64-byte `BpfGuardEvent` rejecting decoder,
  helper bits `PROBE_WRITE_USER=1`, `OVERRIDE_RETURN=2`, `SEND_SIGNAL=4`,
  state-word ABI, bitmap map contract.
- **eBPF (`bpf_guard.rs`):** `#[lsm(hook="bpf_prog")]`,
  `#[tracepoint] syscalls/sys_enter_bpf`, BTF-gated
  `#[kprobe] check_helper_call` reading raw 32-bit `bpf_insn->imm`; per-program
  helper bitmap; own-PID suppression; bounded ring.
- **Core (`bpf_guard.rs`):** attach ladder, mandatory maps, honest status,
  bounded drain, `BPF_GUARD_*` commands.
- **Control (`coreipc_bpf_guard.go`, `xdr_bpfguard.go`):**
  `XDR.BPF_ANOMALY` (observe), `XDR.BPF_ROOTKIT_HELPER` (≥2 high-risk helpers in
  1 h or load from `/tmp`, `/dev/shm`, shell lineage; observe, never kill),
  TOLERATED loader profiles.
- **Acceptance:** loading a test BPF object that uses
  `bpf_probe_write_user`/`bpf_override_return` produces the event with helper
  bitmap and loader pid/inode within 1 s (kernel host required → NOT_TESTED
  here); compile + decoder/unit gates green.

### AP-3 — 8-domain cross-view verifier and raw-socket/BPFDoor audit
- **Core (`cross_view.rs`):** periodic + event-triggered verification of
  - eBPF id-gap: `BPF_PROG_GET_NEXT_ID` vs sequential `BPF_PROG_GET_FD_BY_ID`
    (programs/maps/links) → `XDR.HIDDEN_BPF_PROG`,
  - direct `NETLINK_SOCK_DIAG` (`inet_diag_req_v2`, `packet_diag_req` with
    `PACKET_SHOW_FILTER=0x20`) vs `/proc/net/*` and tap allowlist → BPFDoor /
    VoidLink evidence,
  - `bpf_iter`/`EXEC_EVENTS` memory vs `getdents64(/proc)` vs
    `/proc/<pid>/stat` → `XDR.HIDDEN_PROCESS`,
  - `/sys/module` vs `/proc/modules` vs `tainted` vs
    `/sys/kernel/tracing/enabled_functions` → `XDR.LKM_HIDDEN`,
    `XDR.FTRACE_HOOK_ANOMALY`,
  - `/proc/<pid>/maps` library cross-view.
- **eBPF (`iter.rs`):** `iter/task|tcp|udp|bpf_prog|bpf_map` (BTF-gated),
  `lsm/socket_create` (AF_PACKET), `lsm/socket_setsockopt`
  (`SO_ATTACH_FILTER`/`SO_ATTACH_BPF`), BTF-gated `kprobe/sk_attach_filter`.
- **Control:** `CROSS_VIEW_REPORT`/`CROSS_VIEW_EVENTS` parsers + rules
  `XDR.HIDDEN_*`, `XDR.PORTLESS_RAW_TAP`, `XDR.BPF_LINK_TAMPER` (Observe).
- **Acceptance:** simulated `packet_diag` raw socket from `/tmp` is reported;
  simulated `getdents64`/`GET_NEXT_ID` hiding produces a contradiction.

### AP-7 — unified `PermitV1` broker and anti-FP hardening

  `inode`, `allowed_parents`, `scope`, `valid_from/until`,

  without breaking `gedefense.toml`.
- Persistent encrypted TTL review queue; signed `QUARANTINE_PRUNE`

### AP-8 — optional Chameleon Identity Mode (opt-in install/hardening profile)
- No runtime self-mutation. Central install manifest
  (`/etc/<neutral-vendor>/<install-id>.conf`) + CLI flags for every hardcoded
  socket/path/BPF-root; neutral systemd unit names + dynamic loopback/Unix
  socket ports; Aya-time neutral program/map names (`bpftool prog list` shows no
  `gedefense`/`styx`/`titan` strings); auth via `(dev, ino)` + SHA-256 +
  `SO_PEERCRED` + HMAC only (no `comm` dependency). Signed local VGT admin
  audit retains the real mapping.

### AP-9 — ARES self-defence: TUF anti-poisoning, backpressure, RBAC, anti-truncate
- `S09`: 2-of-3 Ed25519 threshold signatures on feed/rule manifests, role
  separation (root/content/snapshot), short `expires_at`, monotonic anti-rollback
  `epoch` high-water register; local semantic anti-poisoning guard before
  activation (≤20 % deletion diff, immutable system/CORE_QUARANTINE_FORBIDDEN_
  ROOTS zone, no `0.0.0.0/0`/wildcards, RE2 linear-complexity check); cell-helper
  parser isolation + Last-Known-Good rollback.
- `S12`: two-class rings (`SEC_CRIT_EVENTS` high-priority ring for
  `CRED_GUARD`/`BPF_GUARD`/`LKM`/`HIDDEN_*`/`SELF_TAMPER`), per-cgroup/UID token
  bucket with aggregated `XDR.TELEMETRY_FLOOD_SUPPRESSION`, hard quotas + disk
  reserve, honest `capability.degraded` on controlled overflow.
- `R6`/`S08`/`S15`: API RBAC (`Observer` read-only, `Operator` policy,
  `Critical-Unlock` with step-up + brute-force lockout) and immediate
  out-of-band witness push for `SBC-EVID-08` tamper before local log truncation.

## 5. Integration & conflict protocol

- One owner per file set; the seams in §3 are edited only by the integration
  owner (this root agent), serially.
- Every AP reports its public API changes; the integration owner refreshes the
  seams in one batch and re-runs all gates.
- `scripts/security-audit.sh` gains per-AP anchors only via the integration
  owner, after the code is reviewed, so the audit cannot be "greened" by a
  comment.
- `Next.md` is updated after each checkpoint with commands/exit codes.

## 6. Post-AP-10 phase — VGT refactoring plan (objective addition)

After AP-0…AP-10 are complete and the full gate matrix is green, the
`GeDefense_Linux_Refactoring_Plan.md` (workspace root) is executed:
structure-only, wave by wave, no business-logic changes, per-file builds and a
per-wave gate (`make test`, `make test-race`, `make fuzz-smoke`, `make full`,
VM/kernel-load test for the Rust/eBPF waves) plus a local commit per wave.
Waves: (1) Go backend same-package splits, (2) Web UI modularization with
`//go:embed`/Makefile/anchor updates, (3) Rust core submodules
(`ebpf_loader`/`ipc/*`/`sysctl_broker`/`poller` + quarantine/canary/malware),
(4) Rust eBPF split with `#[inline(always)]` on every extracted helper and a
real kernel-load test after each split, (5) script/audit/test splitting while
keeping every security-audit anchor active.
