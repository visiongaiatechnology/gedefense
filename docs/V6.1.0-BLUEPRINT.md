# GeDefense Linux 6.1.0 — Build Blueprint (binding)

Status: ACTIVE implementation contract for the 6.1.0 increment.
Base: `6.0.3` (tag `f3d524d`). Target version: **6.1.0**.

This document is the single source of truth for names, routes, payloads and file
ownership while 6.1.0 is built. Deviations must be recorded here first.

## 0. Non-negotiable constraints

- Go control plane must **not** import `os/exec`, `exec.Command` or `syscall.Exec`
  (`scripts/security-audit.sh` fails the build otherwise). No shell primitives.
- New Go/JS/CSS files are **<= 500 lines**; split into sub-packages/folders.
- New backend logic lives in `control/internal/<pkg>` (pure, testable) with thin
  `main`-package handlers. New UI lives in `control/web/v61/**`.
- Every new setting is registered in the fabric schema, persisted, validated and
  editable/disable-able from the dashboard. Defaults are safe (feature off where
  it changes host behaviour).
- All new UI text goes through `t()` / `data-i18n`; every key exists in **all four**
  catalogues (`de`, `en`, `ru`, `zh-CN`) in `control/web/i18n.js`.
- No `innerHTML` in new frontend code. DOM APIs only. `textContent` for operator data.
- Fail-secure and fail-honest: when a kernel/helper capability is missing, the API
  reports `capability` / `reason`; it never reports "enforced" for an unapplied plan.
- `go.mod` stays dependency-free (stdlib only). No new external Go modules.

## 1. Cross-compilation and toolchain (Linux target)

Build/verify commands (from the repository root):

```powershell
$env:GOTOOLCHAIN='local'
$env:CGO_ENABLED='0'; $env:GOOS='linux'; $env:GOARCH='amd64'
Push-Location "control"
go build ./...; go vet ./...; go test -c -o gedefense-control.test .
Pop-Location
```

`go test` cannot execute Linux test binaries on this host. Compiling the test
binary (`go test -c`) is the required local evidence; state that honestly.
The Rust crates are type-checked on the build host against the installed
`x86_64-unknown-linux-musl` standard library: `cargo check -p gedefense-core`
and (with `RUSTFLAGS='-C panic=abort'`) `cargo check -p gedefense-ebpf` pass,
and `cargo test -p gedefense-common` runs natively. The BPF verifier and
`bpf-linker` build still require the pinned Linux toolchain
(`TOOLCHAINS.lock`), so kernel acceptance is marked NOT_TESTED here.

## 2. Kernel / sensor decisions (Module B, C, D)

- **C TLS ClientHello / QUIC:** userspace passive sensor, no eBPF:
  `AF_PACKET` raw socket + classic BPF filter (TCP dport 443/8443 with payload
  whose first byte is `0x16`, UDP dport 443 with QUIC long-header bit). First
  <= 1536 payload bytes are fed to the existing `ParseClientHello` and
  `TLSSecurityEngine` (`l7_tls.go`). Overhead stops after the handshake.
- **C flow budget:** read the kernel-maintained per-socket counters via
  `NETLINK_SOCK_DIAG` (`INET_DIAG_INFO` / `tcp_info.bytes_received`,
  `bytes_acked`, `segs_in`, `segs_out`) for established local ports 443/8443.
  This is the counter pair the kernel already maintains (sock_ops equivalent),
  bounded in a userspace LRU. No XDP map, no port-spoof eviction.
- **B crash storm:** eBPF `sched_process_exit` / `signal_deliver` tracepoints
  (new Rust module `rust/gedefense-ebpf/src/worker_guard.rs`, loaded by
  `gedefense-core`) are the primary source, with a kernel proc-connector
  (netlink `CN_PROC`) source in Go as the portability fallback. Both deliver the
  same `WorkerCrashEvent` shape to the Go correlator.
- **B exec/mmap lock:** reuse the existing Titan exec gate; Go classifies web
  worker cgroups (nginx/apache2/httpd/php-fpm workers, never master/control
  units) into `StrictCgroups` with `JIT_ALLOW = 0`.
- **D socket creation:** extend the existing `gedefense_cell_socket_create` LSM
  policy flag word (new bits defined in `gedefense-common`), then apply the flags
  per web-worker cgroup through the existing `CELL_POLICY_SET` path.

## 4. Module requirements (backend)

### A — Web exposure & posture
- Discovery without exec: `/proc/*/exe` readlink, comm, uid, `/proc/net/tcp{,6}`
  listen inodes -> pid via `/proc/*/fd` (bounded).
- ELF `.rodata` scan with `debug/elf`: version string, `--with-*` flags, static
  OpenSSL evidence; cap section read (32 MiB) and server count.
- Config parse: roots `/etc/nginx`, `/www/server/nginx/conf`,
  `/www/server/panel/vhost/nginx`, Apache dirs if present. Bounded recursive walk,
  skip symlinks outside root, max 1 MiB/file, max 2048 files. Evidence file:line.
- Loopback ALPN probe: `crypto/tls` dial 127.0.0.1:<listen port>, SNI from first
  `server_name` (fallback `localhost`), `NextProtos: ["h2","http/1.1"]`,
  InsecureSkipVerify for the *probe only*, 3 s timeout, one probe per port.
- Advisory catalogue: nginx/openssl version-range matching, includes
  CVE-2026-123007, CVE-2026-123633, CVE-2026-121810 with the workarounds from the
  mission; each match names reachability (ALPN/h2 active, QUIC active, listener
  beyond loopback) and a mitigation. Unit tests for range matching and the
  "affected only when reachable" rule.
- Cache result (TTL = `scan_interval_seconds`, default 60 s); `POST scan` forces
  refresh with a per-server rate budget.

### B — Worker integrity watch
- Registry from settings; classify `comm` (trim to 15 bytes), uid, cgroup id via
  `/proc/<pid>/cgroup`.
- Sources: eBPF (core IPC, later) and netlink proc connector. Interface:
  `type CrashSource interface { Start(ctx, sink) error; Status() (mode, reason) }`.
  Netlink source subscribes `PROC_EVENT_EXIT`, filters registered comm/uid,
  maps `exit_code & 0x7f` to fatal signals (SEGV=11, BUS=7, ILL=4, ABRT=6),
  ignores clean exits and `SIGTERM`/`SIGKILL` from panel reloads.
- Correlation: per comm+uid window; 1 crash -> medium audit event; >=3 in 60 s ->
  CRITICAL incident + case `XDR.WORKER_CRASH_STORM` (dedupe by comm+window).
  Correlation with open :443 peers uses the TLS sensor's recent peer snapshot.
- Strict classification: never include master/control units (systemd, `nginx:
  master process`, panel reload helpers). Exclude list from settings and a
  built-in denylist. Produce a Titan scope plan {strict_cgroups, jit_cgroups=[]}
  and report `applied` only after the existing command succeeded.

### C — TLS/ALPN sensor & control-storm budget
- AF_PACKET sensor with BPF filter as described; parse with existing
  `ParseClientHello`; feed `TLSSecurityEngine.InspectHandshakeDetailed`; keep
  bounded rings (handshakes 256, events 256) and per-peer counters.
- Flow snapshot from `INET_DIAG`; bounded LRU; compute
  `avg_pkt_len = rx_bytes / max(segs_in, 1)`.
- Storm predicate exactly: `rx_bytes > threshold && rx_bytes > ratio*tx_bytes &&
  avg_pkt_len < avg_limit && segs_in > min_pps_ratio*max(segs_out,1)`.
  Alert-only by default; staged response: alert incident -> throttle plan
  (per-peer TTL) -> ban only when storm persists across two evaluations or a
  worker SIGSEGV correlates. Never ban a flow that fails the avg-length test.
- Unit tests for predicate boundaries (large upload must NOT trigger).

### D — LPE kill-chain
- Socket policy plan per web-worker cgroup with deny bits matching the Rust
  constants (section 6), applied only through the existing kernel policy command
  with explicit capability reporting.
- StyX `web-ingress-only` profile: allow loopback + configured backend CIDRs +
  DNS servers; deny everything else. Render the plan and apply through the
  existing StyX policy path only when `styx_profile=true`.
- Hardening baseline: ASLR check/enforce through the existing hardening sysctl
  path; SCTP/DCCP/RDS module checks from `/proc/modules` + `/etc/modprobe.d`;
  enforceable entries report a concrete apply/rollback plan.

### E — Memory-safe edge terminator (lead)
- Go `crypto/tls` + `net/http` front proxy, default off, loopback listen,
  `http.Server.HTTP2` hard limits (RFC 9113), request bounds, inline WAF checks,
  upstream HTTP/1.1, incidents for blocked requests. Lead implements.

## 6. Rust kernel changes (owner: lead)

`rust/gedefense-common/src/lib.rs`:
- `pub const CELL_LSM_DENY_AF_PACKET: u8 = 1 << 1;`
  `..._AF_TIPC = 1 << 2; ..._AF_VSOCK = 1 << 3; ..._SCTP = 1 << 4;`
  `..._DCCP = 1 << 5; ..._RDS = 1 << 6;` (bit 0 stays NON_UNIX_SOCKET).
- `pub struct WorkerCrashEvent { pid: u32, uid: u32, gid: u32, cgroup_id: u64,
  signal: u32, exit_code: i32, comm: [u8;16] }` with `#[repr(C)]`.

`rust/gedefense-ebpf/src/worker_guard.rs` (new module, `mod worker_guard;`):
- `WORKER_GUARD_STATE: Array<u64>` (enable bit), `WORKER_COMMS: HashMap<[u8;16],u8>`,
  `WORKER_UIDS: HashMap<u32,u8>`, `WORKER_CRASH_EVENTS: RingBuf` (256 KiB),
  counters for emitted/dropped.
- `#[tracepoint] fn gedefense_worker_exit` reading current comm/uid/cgroup and the
  exit code from `TracePointContext` args; `fn gedefense_worker_signal` reading
  the signal number; both emit only for registered comm/uid and only fatal
  signals, at most one event per pid.
- `main.rs`: add `mod worker_guard;` and add the new deny bits to
  `gedefense_cell_socket_create` checks (socket family / protocol switches).

`rust/gedefense-core`:
- attach the two tracepoints (non-fatal when unavailable), take the maps,
  new command family `WORKER_GUARD_*` (`SET`, `EVENTS`, `STATUS`), and count
  attach capability honestly.
- Go client: new file `control/coreipc_worker.go` with `WorkerGuardSet`,
  `WorkerGuardEvents`, `WorkerGuardStatus` following the `styxCommand`
  unknown-command capability pattern.
