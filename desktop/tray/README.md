# gedefense-tray

Desktop tray client for GeDefense (Qt6 / C++17). It is a read-only consumer of
the control plane's status socket: one request line, one JSON reply line, no
privileges, no network access, no child process other than the explicitly
requested console launch.

```
/run/gedefense/gedefense.sock  (AF_UNIX SOCK_STREAM, frozen wire contract v1)
        │
        ├─ request : {"v":1,"op":"status"}\n              (≤ 256 bytes)
        └─ reply   : one JSON object + "\n"               (≤ 4096 bytes)
```

## Contents

| Path | Purpose |
| --- | --- |
| `src/theme.h` | every colour, radius, font and spacing token (copied verbatim from `integration/astraeaos/gedefense-shell.cpp`) |
| `src/app_paths.h` | fixed absolute paths (socket, console binary) and the socket path validator |
| `src/status_payload.h/.cpp` | the **only** place JSON is interpreted: strictly validated, bounded struct |
| `src/status_client.h/.cpp` | `QLocalSocket` transport: one request in flight, 2 s timeout, bounded backoff, staleness |
| `src/tray_controller.h/.cpp` | `QSystemTrayIcon`, icon per state, tooltip, minimal menu, click-to-toggle |
| `src/status_popup.h/.cpp` | frameless flyout, clamped to the screen, keyboard operable, plain-text only |
| `src/state_labels.h/.cpp` | state → translated name, badge, silhouette description, icon, colour |
| `src/state_icons.h/.cpp` | renders the bundled SVGs (with a painted fallback if the resource is missing) |
| `resources/` | `gedefense-tray.qrc` plus four hand-written SVGs (four distinct silhouettes) |
| `i18n/` | `gedefense-tray_{de,en,ru,zh}.ts`, 75 messages, complete |
| `packaging/` | application entry and autostart entry |
| `screenshots/` | reference renders of the flyout from the verification run (regenerated by `tst_popup_render`) |
| `tests/` | Qt Test suites: payload validation, transport against a real `QLocalServer`, offscreen renders |

## Build

Dependencies (Ubuntu 24.04 / Debian):

```bash
apt-get install -y qt6-base-dev qt6-base-dev-tools qt6-svg-dev \
                   qt6-tools-dev qt6-tools-dev-tools qt6-l10n-tools cmake ninja-build
```

`Qt6::Svg` is required to rasterise the bundled silhouettes; `Qt6::LinguistTools`
is optional (see *Translations*).

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build
QT_QPA_PLATFORM=offscreen ctest --test-dir build --output-on-failure
```

Every translation unit of this project is compiled with
`-Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wsign-conversion
-Wold-style-cast -Wnon-virtual-dtor -Woverloaded-virtual -Wdouble-promotion
-Wformat=2 -Wcast-qual -Wnull-dereference -Wduplicated-cond
-Wduplicated-branches -Werror` (moc/rcc generated sources are excluded from
those flags).

## Behaviour

* polling every 3 s; one request in flight at a time
* 2 s request timeout, then `abort()` and a clean restart
* failures use bounded exponential backoff 2 s → 30 s with ±25 % jitter
* data is marked stale 15 s after the last successful answer
* **the client owns the `Stopped` state**: no answer never renders as healthy
* the flyout shows the last known values only while they are not stale; a stale
  alert is never kept on screen
* no animation at all, therefore a reduced-motion preference is honoured by
  construction; the state is always carried by silhouette **and** badge text

## Translations

Source strings are German; `i18n/*.ts` are compiled to `.qm` by `lrelease`
during the build (when `Qt6::LinguistTools` is available) and installed to
`share/gedefense-tray/i18n`. The client looks for catalogues in

1. `<application dir>/i18n`
2. `<application dir>/../share/gedefense-tray/i18n`
3. `/usr/local/share/gedefense-tray/i18n`
4. `/usr/share/gedefense-tray/i18n`

using `QLocale::system()`. When no catalogue matches (`C`, `fr_FR`, …) or when
`.qm` files were never compiled, the built-in German strings are used. The `.ts`
files are never parsed at runtime.

Regenerating the catalogues after changing a `tr()` string:

```bash
lupdate -no-obsolete -recursive src -ts i18n/gedefense-tray_{de,en,ru,zh}.ts
```

## Verification (this revision)

Run from WSL (Ubuntu 24.04, g++ 13.3.0, Qt 6.4.2, cmake 3.28.3, ninja 1.11.1):

```bash
cmake -S /mnt/c/.../desktop/tray -B /tmp/tray-build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build /tmp/tray-build
QT_QPA_PLATFORM=offscreen ctest --test-dir /tmp/tray-build --output-on-failure
QT_QPA_PLATFORM=offscreen /tmp/tray-build/tests/tst_popup_render --out /tmp/tray-build/screenshots
```

Observed: configure 0, build 31/31 targets with 0 warnings and 0 errors, ctest
3/3 suites green (payload, transport, render), 8 PNGs written.

Screen renders (`build/screenshots`): `01-secure.png`, `02-warning.png`,
`03-alert.png`, `04-stopped.png`, `05-stopped-stale.png`,
`06-long-german-compounds.png`, `07-constrained-viewport.png`,
`08-console-action-disabled.png`; the same set is rendered again with
`QT_SCALE_FACTOR=2` into `build/screenshots-200`. The 100 % set is committed
next to the sources in `screenshots/` as visual reference.

Not verifiable here: real StatusNotifierItem/X11/Wayland tray rendering and
host integration — that needs a desktop session. The offscreen platform has no
tray, so `QSystemTrayIcon::isSystemTrayAvailable()` is false and the client
falls back to presenting the flyout once (see `src/main.cpp`).
